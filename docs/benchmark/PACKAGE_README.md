# TramFlow — итоговый отчёт о бенчмарках

Дата измерений: 3 октября 2026 года.

## Содержимое

- `TramFlow_Benchmark_Report_2026-10-03.pdf` — итоговый отчёт, 15 страниц.
- `TramFlow_Benchmark_Report_2026-10-03.docx` — редактируемая версия.
- `TramFlow_Benchmark_Report_2026-10-03.md` — текст для репозитория; рисунки используют относительные ссылки на `charts/`.
- `charts/` — семь графиков по числовым данным и три фрагмента исходных скриншотов Grafana. Обрезка скриншотов выполнена только для читаемости.
- `analysis.json` — нормализованные итоги 18 запусков, исходные report-показатели, значения по endpoint, проверки согласованности, SHA-256 исходных файлов и архивов.
- `bench_export/benchmarks/results/` — исходные компактные результаты: report.json, benchmark.md, k6-summary.json и system.csv для каждого запуска.
- `benchs/` — все 26 исходных скриншотов Grafana, предоставленных для отчёта.
- `reference_code/` — выбранные файлы из ранее переданного MT_hack-observability-grafana.zip для объяснения сценариев, расчётов и запросов dashboard. Это справочная версия, а не подтверждённая побайтовая копия рабочей директории на машине испытаний.
- `SHA256SUMS.json` — контрольные суммы файлов пакета, кроме самого списка сумм.

## Как читать

Метки R01–R18 в отчёте соответствуют реестру запусков на странице 14. G1–G3 относятся к скриншотам, C1–C3 — к справочному коду, D1–D6 — к официальной документации k6 и Prometheus.

Пакет содержит анализ уже выполненных пользователем испытаний. Новые нагрузочные тесты при подготовке отчёта не запускались. Область измерения — synthetic_mock, тестовый snapshot и прогретый кэш. Нельзя переносить эти числа напрямую на реальную обученную ML-модель или другие данные.

Soak 400 RPS: 45 минут measurement, 1 080 001 запрос, 1 080 000 успешных, одна бизнес-ошибка, ноль пропущенных итераций; p95 9,15 мс и p99 16,98 мс. Короткий тест 500 RPS прошёл без ошибок; 600 RPS нарушил критерий допустимой доли ошибок. Две реплики не подтверждают ускорения; отдельное наблюдение — рост памяти генератора k6.

Численные итоги задержек берутся из business_latency measurement в k6-summary.json и сверены с report.json. Средние процентилей на текущем dashboard не используются как глобальные p95/p99. Неизмеренные показатели не подменены нулями. Отсутствующие cold-start, scale consistency и microbenchmark-артефакты не отмечены как успешные.
